# chore-lottery

Fair chore assignment for families. Parents write chores in plain
language on a [Vikunja](https://vikunja.io) kanban board; an AI
pipeline enriches each card into kid-friendly instructions (simple
steps, an optional how-to video, a checklist graphic); each child
draws **one chore at random** through their personal QR code and sees
nothing else - no sibling comparison, no chore shopping, no swapping
until a parent approves the finished work.

Status: early development. The dev loop below is the contributor
contract; features land card by card.

## How it works

```text
Parent (Vikunja)                chore-lottery                 Kid (phone)
───────────────                 ─────────────                 ───────────
write card, plain words  ──▶   AI augments card
                               (steps, video, graphic)
drag to "Ready"          ──▶   card enters the lottery
                               child scans QR          ──▶   one random chore shown
                               (one at a time, no choice)
                               child marks done + photo ◀──    work finished
approve / reject + notes ──▶   next draw / try again
```

- **Vikunja is the only board UI.** Parents never leave it; this
  service syncs with it in both directions. See
  [`docs/design/sync-architecture.md`](docs/design/sync-architecture.md)
  for the full flow and the backend seam.
- **Event sourced.** Every state change and every AI action is an
  auditable event.
- **Kids get a PWA, not an account.** A personal QR code opens a
  mobile page showing exactly one card.

## Development quickstart

Prereqs: Rust (1.81+), uv, docker compose, pre-commit.

```sh
git clone <this repo> && cd chore-lottery
pre-commit install
cp .env.example .env   # fill in keys; never commit .env
docker compose up -d
uv run --project machinery chore-machinery seed
uv run --project machinery chore-machinery check
```

See `docs/dev-stack.md` for the full dev-stack guide (lands with
board card S1).

Board tooling: the pre-commit `boardkit` hook expects a sibling
checkout of the [boardkit](https://github.com/Shearerbeard/boardkit)
CLI at `../boardkit`; override with `BOARDKIT_HOME=/path/to/boardkit`.

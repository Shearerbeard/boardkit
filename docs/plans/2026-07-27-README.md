# Reproducible dev-process program - plan set (2026-07-27)

Four gated plans produced by a Claude Code planning session (research fan-out:
four Opus surveys of terminalbench-aura process machinery, boardkit, claude-skills,
and the opencode config). No implementation happened in that session; these files
are the deliverable. Each plan follows the plan-discipline template and is
executable by a future board-owner session.

## Sequencing

- Plan 2 is independent and all easy lifts - run first or in parallel.
- Plan 1 stages 1–3 (extraction refresh, template fixes, canary restoration)
  precede Plan 1 stage 4 (Phase 3 skills), which consumes Plan 4 stage 2's
  typed-holes skill. Order: P1.1–1.3 → P4.1–4.2 → P1.4 → P1.5.
- Plan 3 stage 1 rides with Plan 1 stage 5 (aura adoption); stages 2–3
  (seam + Linear) are strictly post-parity. Do not let them delay Phases 3–6.

## Composition contract (the dividing line)

Dated record. Since 2026-08-31 rust-holes is public and the live contract
is stated in its README ("How this composes"); the private labels below
describe the plan as written.

Three artifacts, each standalone, composed only through optional references:

- **boardkit** (public): the gated card board - schema, validator, views,
  review packets, PROCESS/MODEL-CLASSES/REVIEW-TOOLING templates, board-hygiene
  + delegating-work skills. Runs with zero Rust content. Its PROCESS template's
  type-discipline section is a *stub* that names the `typed-holes` skill if
  installed and degrades to "define your language's type discipline here" if not.
- **rust-holes** (private): the full typed-holes + layered red-green playbook,
  templates (DESIGN.md, skeleton conventions, dispatch-brief quotes for
  non-skill executors), golden-frame harness guide, aura-derived exemplars.
  Usable in any Rust repo with no board and no skills installed.
- **claude-skills** (public marketplace): the glue. `typed-holes` skill (rust
  plugin) carries the generic practice; boardkit's board-hygiene skill and
  rust-holes' playbook both reference skills by bare backticked name and must
  keep working when the referenced skill is absent (state the fallback inline).
  Private material (aura exemplars, cost figures, machine paths) never crosses
  into the two public artifacts - same rule as boardkit's publish gates.

## Standing constraints (from the planning session's user directives)

- Do not regress what already works: aura's live board stays validated by its
  current script until boardkit proves byte-identical + new-check triage (P1.5).
- Continue automating validation; prefer machine checks over prose rules.
- Both-sides fixes: where aura and boardkit disagree, the plans name a fix on
  each side rather than declaring one canonical.
